# Aidit-Code — Product Requirements Document (PRD)

> **게시글마다 백엔드 샌드박스에서 도는 코드 에이전트(pi agent)에 여러 사람이 함께 붙어, AI on/off로 채팅하며 협업 코딩하는 플랫폼**
> Status: PoC (Proof of Concept) · Version: 0.2 · v2(동시 병렬 협업 에이전트) · Date: 2026-06-29

---

> ## Δ from Aidit — 부모 대비 무엇이 바뀌었는가
>
> Aidit-Code는 부모 **Aidit**의 형제 프로젝트다. **그린 인광 CRT 레트로 터미널 디자인 시스템은 100% 그대로 계승**하고, **동작 모델만** 교체했다.
>
> | 영역 | 부모 Aidit | Aidit-Code (이 문서) |
> |------|-----------|----------------------|
> | 핵심 동작 | 글 스레드 = 공유 AI **대화 컨텍스트** | 글 스레드 = 샌드박스에서 도는 **코드 에이전트 세션** |
> | AI 실행 위치 | **클라이언트**가 BYOK로 Google Gemini 직접 호출 | **백엔드 샌드박스**의 pi agent(서버 운영자 LLM 키) |
> | LLM 키/비용 | **BYOK** — 사용자 본인 Gemini 키, 비용 사용자 부담 | **서버 .env**의 OpenAI-compatible 키, 비용 **서버 부담** |
> | 커뮤니티 | 사용자 생성 커뮤니티 + AI **페르소나** | **전면 제거** — 게시글(Post)만 존재, 홈=게시글 피드 |
> | 컨텍스트 관리 | **클라이언트 128K 요약 엔진**(contextEngine.ts) | **pi agent 런타임이 자체 관리** — 서버는 SoT·SSE 릴레이만 |
> | 글의 산출물 | 텍스트 대화 | 코드 에이전트가 **샌드박스에서 파일 생성/쉘 실행/패키지 설치** |
> | Gemini 연결 배지 | 헤더에 GEMINI LED 배지 | **삭제** — 대신 Thread 내 에이전트/샌드박스 상태 인디케이터 |
>
> 부모 고유의 **BYOK · 커뮤니티/페르소나 · 128K 클라이언트 요약**서술은 본 문서에서 새 모델로 정정·삭제됐다.

> ## Δ v2 — 동시 병렬 협업 에이전트(병렬 추론 + 직렬 부수효과)
>
> v0.1은 게시글당 단일 pi agent 세션에 N명이 attach(fan-out)하되, **동시 질문을 단일 활성 턴 + FIFO 큐로 직렬화**했다. 그 결과 내 질문이 남의 긴 작업이 끝날 때까지 pending에 묶이는 **머리-막힘(head-of-line blocking)** 이 발생했다. v2는 이 직렬 병목만 제거하고, **단일 세션·단일 공유 컨텍스트·단일 샌드박스**라는 협업 모델은 **그대로 유지**한다.
>
> **opt-in(기본 OFF):** 이 v2 동작은 **게시글 생성 시 체크박스로 명시적으로 켜야** 적용된다. 기본값은 OFF = v0.1 직렬 동작이며, 모드는 **글 단위로 생성 시 1회 확정**된다(이후 변경 불가). 켜기 전까지 기존 단일 활성 턴 + FIFO 동작이 그대로 보존된다.
>
> | 영역 | v0.1 (단일 활성 턴 + FIFO) | v2 (이 문서) |
> |------|----------------------------|--------------|
> | 동시 질문 처리 | 활성 턴 1개, 나머지는 큐에서 **직렬 pending** | N명의 질문이 **각자 독립 턴으로 동시 병렬 추론** — 내 답이 즉시 스트리밍 |
> | 에이전트 출력 | **단일 스트림** 1개를 전원이 공유 | **동시 다중 스트림**(여러 AGENT_REPLY가 동시에) — 모두에게 보임 |
> | 답글 귀속 | 활성 턴 1개의 답을 모두가 봄 | 각 답글이 **자기 HUMAN 질문에 1:1**(replyToId)로 묶임 |
> | 파일 부수효과 | 턴이 직렬이라 자연히 단일 | 추론은 병렬이되 **파일 쓰기/도구 실행은 샌드박스 단위 단일 직렬 실행기**로 순차 적용(머지 불필요) |
> | 공유 컨텍스트 | 단일 convo | **단일 convo 유지** — 각 병렬 턴은 시작 시 스냅샷을 읽고 완료 순으로 직렬 커밋 |
> | 세션 상태 배지 | IDLE/RUNNING(단일) | **활성 턴 수**("N개 작업 진행 중") |
> | 비용 | 직렬 1턴분 | 동시 N턴 = **N× 토큰**(동시성 본질 비용) |
>
> **핵심 한 줄**: 여러 사용자의 요청이 **동시에 병렬로 추론**되어 각자의 답이 남의 긴 작업과 무관하게 **즉시 스트리밍**되고, 파일 같은 **부수효과는 직렬로 안전하게** 적용된다. fan-out은 "단일 출력을 공유"에서 "**동시 다중 출력을 모두가 공유**"로 확장됐다.
>
> **왜 이 모델인가(대안 기각)**: per-user 프로세스 격리는 공유 컨텍스트를 파괴하고 N프로세스가 같은 작업공간에 lock 없이 써 파일 안전을 깨뜨린다. 입력 배칭(N개 질문→1턴)은 귀속 붕괴·무관 요청 혼합을 부른다. **병렬 추론 + 직렬 부수효과**만이 동시성·협업·파일 안전·1:1 귀속을 동시에 만족한다.
>
> **알려진 한계(정직히)**: 동시 N턴 = 토큰 N배 비용 / 멀티유저로 공유 convo 한도가 더 빨리 참(상향·요약 필요) / 같은 파일을 동시에 건드린 턴은 직렬 적용 시 **last-wins**(논리적 레이스 잔존, 필요 시 같은 파일 턴만 직렬 폴백) / 동시 발사된 턴은 서로의 '그 순간' 입력을 못 볼 수 있음(컨텍스트 staleness, 수용).
>
> v0.1의 "동시 질문은 직렬로 pending된다 / 에이전트 출력은 한 번 생성되어 단일 스트림으로 전원에게 전달된다"는 서술은 본 문서에서 v2 모델로 정정됐다(아래 §·FR 인라인 갱신).

## 1. 배경 & 영감 (pi agent · 코드 에이전트)

본 제품은 **코드 에이전트**(LLM이 셸·파일 도구를 직접 호출해 코드를 작성/실행하는 에이전트) 흐름과,
부모 Aidit이 영감을 받았던 **"여러 뷰어가 하나의 살아있는 AI 세션을 공유하며 동시에 개입(steer)한다"** 는 fan-out 모델에서 출발한다.

다만 부모 Aidit이 *대화 컨텍스트*를 공유했다면, Aidit-Code는 **실행 가능한 코드 에이전트 세션**을 공유한다. 핵심 통찰은 다음과 같다.

- 코드 에이전트는 **셸/파일/패키지 도구**를 호출해 실제로 코드를 만들고 돌린다. 그 작업 공간(워크스페이스)이 필요하다.
- 그래서 **게시글마다 백엔드에 샌드박스 디렉토리 1개**를 1:1로 붙이고, 채팅방이 열리면 그 방은 **샌드박스에서 도는 pi agent 세션**이 된다.
- 부모처럼 각자의 LLM에서 따로 도는 게 아니라, **모든 참여자가 같은 에이전트 세션에 attach**해서 출력을 실시간으로 함께 본다(fan-out). **v2부터는 여러 사용자의 질문이 동시에 병렬로 추론되어, 단일 출력 스트림이 아니라 동시 다중 스트림이 모두에게 중계**된다(아래 §3·FR-4/FR-5 참조).

따라서 Aidit-Code는:

- **백엔드를 코드 에이전트 호스트**로 만든다. 웹 백엔드가 opencode server / pi agent 처럼 동작하며, **본 프로젝트는 pi agent를 런타임으로 채택**한다.
- 컨텍스트 압축/요약 로직을 클라이언트로 포팅하지 않는다. **컨텍스트·히스토리·요약은 pi agent 런타임의 책임**이다(부모의 클라이언트 128K 요약 엔진은 폐기).
- LLM은 **OpenAI-compatible**로 동작하며 `apikey`/`baseURL`은 **서버 `.env`** 에만 둔다(클라이언트 미노출).

> 라이선스: **MIT** (부모 Aidit와 동일 기준).

## 2. 제품 한 줄 정의

**Aidit-Code** = 게시글마다 **백엔드 샌드박스에서 도는 코드 에이전트(pi agent)** 에 여러 사람이 함께 붙어,
**AI on/off로 채팅하며 협업 코딩**하는 플랫폼. 에이전트는 샌드박스 안에서 **파일을 만들고, 쉘을 돌리고, 패키지를 설치**하며,
모든 참여자는 같은 세션에 attach해 그 출력을 **실시간으로 함께** 본다. **여러 사람이 동시에 던진 요청은 각자 독립 턴으로 병렬 추론되어 답이 즉시 스트리밍**되고(머리-막힘 없음), **파일 등 부수효과는 직렬로 안전하게** 적용된다(v2). **LLM 추론 비용·키는 서버 운영자가 부담**한다(BYOK 없음).

## 3. 핵심 차별점 (Why Aidit-Code)

1. **게시글 = 살아있는 코드 에이전트 세션** — 부모처럼 텍스트 대화만 쌓는 게 아니라, 글마다 붙은 샌드박스에서 **pi agent가 실제 코드를 작성·실행**한다. 채팅방을 열면 그 방이 곧 에이전트 세션이다.
2. **여러 사람이 한 에이전트에 동시 attach (fan-out) + 동시 병렬 협업(v2)** — 같은 세션에 붙은 모든 클라이언트가 에이전트 토큰·도구 호출·파일 변경을 **동일하게 실시간 중계**받는다. v2부터 **여러 사용자의 요청은 각자 독립 턴으로 동시에 병렬 추론**되어, 내 답이 남의 긴 작업 뒤로 밀리지 않고 **즉시 스트리밍**된다(머리-막힘 제거 = 진짜 동시 협업). 출력은 더 이상 단일 스트림이 아니라 **동시 다중 스트림**이며, 각 답글은 **자기 질문에 1:1로 귀속**(replyToId)되어 모두에게 보인다. 반면 **파일 쓰기·도구 실행 같은 부수효과는 샌드박스 단위 직렬**로 적용돼 충돌·머지가 필요 없다.
3. **샌드박스 = 모든 permission 허용** — 클라이언트가 코드 에이전트에 붙는 형태라 샌드박스 디렉토리 내부에서는 **파일 생성/삭제·가상환경(venv) 세팅·패키지 설치·쉘 실행**이 가능하다. 격리 경계는 디렉토리(경로 탈출 차단)·리소스·네트워크 정책으로만 둔다.
4. **서버 키 모델(BYOK 폐기)** — 사용자는 키를 입력/보관하지 않는다. LLM은 OpenAI-compatible로 **서버 `.env`의 키/baseURL**로 호출되고, **비용은 서버가 부담**한다. 사용자는 글을 쓰고 채팅만 하면 된다.
5. **도구 호출·터미널 출력이 채팅 버블로** — 에이전트가 돌린 셸 명령(`$ <cmd>`)과 그 출력이 **채팅 안의 버블**로 렌더되어, 협업 코딩 과정이 그대로 스레드에 남는다.

## 4. 대상 사용자 유형 (User Types)

> 여기서 "유형"은 **제품 기획상 타깃 사용자**를 가리킨다. 부모 Aidit의 **AI 페르소나** 기능은 본 프로젝트에서 전면 삭제됐다(§5).

| 사용자 유형 | 설명 | 핵심 니즈 |
|---------|------|----------|
| **작성자(Poster)** | 작업/문제를 게시글로 던지는 사람 | 글을 올리면 곧바로 전용 샌드박스 + 코드 에이전트가 준비됨 |
| **협업자(Collaborator)** | 같은 스레드 세션에 붙어 함께 지시하는 사람 | 채팅하듯 가볍게 의견 + AI on으로 에이전트에 작업 지시·스티어링. **내 요청은 남의 진행 중 작업과 무관하게 즉시 병렬로 처리(v2)** |
| **관전자(Observer)** | 에이전트의 작업을 실시간으로 보는 사람 | 토큰 스트림·도구 호출·파일 변경을 실시간 fan-out으로 시청. **여러 답글이 동시에 스트리밍되는 다중 진행 상황을 한눈에(v2)** |
| **탐색자(Browser)** | 인기 게시글을 둘러보는 사람 | 홈 게시글 인기 피드(커뮤니티 개념 없음) |

전제: PoC 단계 사용자는 **코드/터미널에 익숙한** 기술 친화적 얼리어답터. (부모와 달리 **개인 API 키 발급은 불필요** — 서버가 LLM을 제공.)

## 5. 범위 (Scope)

### 5.1 In Scope (PoC)
- 사용자 식별: **username + password 로그인**(회원) 또는 **게스트(닉네임만, `#hex4` 부여)** → 서버 JWT 토큰 발급(토큰만 localStorage 저장). **API 키 입력/저장 개념 없음**(서버 `.env`).
- 게시글 작성/조회, **홈 게시글 인기 피드**(hot/new), 추천(업보트), 북마크.
- **글 작성 시 Sandbox 1:1 자동 생성**(status=CREATING→READY 비동기).
- 협업 채팅 스레드(좌: 타인+에이전트, 우: 본인).
- **AI on/off 토글** → on이면 사람 메시지를 샌드박스 pi agent 세션에 주입해 에이전트 턴 시작.
- 에이전트의 **도구 호출·터미널 출력**을 TOOL_CALL/TOOL_RESULT 버블로 렌더, (선택) **워크스페이스/파일 트리 패널**.
- 스레드 **실시간 fan-out**(다중 사용자 동일 세션 attach, SSE).
- **동시 병렬 협업(v2)**: 단일 세션·단일 공유 컨텍스트·단일 샌드박스를 유지한 채, **여러 사용자 요청을 독립 턴으로 동시 병렬 추론**(각 답 즉시 스트리밍, 머리-막힘 없음)하고 **파일/도구 등 부수효과는 샌드박스 단위 직렬 실행기로 순차 적용**한다. 답글은 자기 질문에 1:1 귀속(replyToId). 동시 inflight 턴 수 상한(`MAX_CONCURRENT_TURNS`, 비용/부하 제어) + 초과분 공정 큐. **이 모드는 글 작성 시 체크박스로 opt-in해야 켜진다**(기본 OFF = v0.1 직렬; 생성 시 1회 확정·변경 불가). **1인 1활성턴**: 한 사용자는 자기 턴을 1개만 동시 진행한다(병렬은 사용자 간에만) — 내 턴 진행 중 내 전송은 잠기고 남의 턴은 막지 않는다 → 동시 턴 수 ≤ 동시 활성 사용자 수.
- **샌드박스 라이프사이클**: create → attach → run → interrupt/steer → suspend → resume → cleanup.
- LLM: **OpenAI-compatible 단일 런타임**(서버 `.env`의 `API_KEY`/`BASE_URL`/`MODEL`, PoC 기본=GitHub Models `openai/gpt-4o-mini`), 런타임=**pi agent**.

### 5.2 Out of Scope (PoC 이후)
- **BYOK / 클라이언트 직접 LLM 호출** — 완전 제거(설계상 서버 키만). 다중 LLM 프로바이더 선택 UI도 비범위.
- **커뮤니티 / 페르소나** — Community 검색·상세, CreateCommunity, 페르소나 편집을 **전면 삭제**(게시글만 존재).
- **컨테이너 강화 격리**(Firecracker / gVisor / Docker) — PoC는 호스트 디렉토리 격리 + 프로세스/cgroup-lite + 경로 탈출 차단까지. 본격 컨테이너 샌드박싱은 후속.
- 샌드박스당 **동시 다중 활성 *세션*(프로세스)**(PoC는 샌드박스당 활성 세션 1개 유지). — 참고: v2의 "동시 병렬"은 **세션을 늘리는 게 아니라 단일 세션 안에서 턴을 병렬화**하는 것이며(공유 컨텍스트·단일 샌드박스 보존, §Δ v2), 이는 In Scope다. per-user 프로세스 격리는 비범위.
- OAuth/이메일 인증, 계정 복구, 비밀번호 변경/리셋.
- 이미지/파일 업로드 첨부, 리치 미디어, 전문(full-text) 검색.
- 모바일 네이티브 앱(웹/PWA만), 푸시 알림.
- **게스트 → 회원 승격(account promotion)**: 게스트(`닉네임#hex4`, `passwordHash=null`)와 회원이 별개 User 행이라 병합 경로가 없다(게스트로 쌓은 콘텐츠는 게스트 정체성에 귀속). 향후 별도 엔드포인트로 검토.

## 6. 기능 요구사항 (FR)

### FR-1 홈 / 탐색
- **FR-1.1** 홈 화면에 **게시글 인기 피드**(카드 리스트)를 노출한다. 정렬 `sort=hot|new`, 인기 점수 `hotScore = f(추천 수, 메시지 수, 최신성)`. 커서 페이지네이션. PoC 공식은 TRD 참조.
- **FR-1.2** 각 피드 카드는 해당 게시글 **샌드박스 상태 요약**(예: READY/RUNNING/SUSPENDED/ERROR)을 표시한다. (부모의 커뮤니티 검색은 **제거** — 커뮤니티 개념 없음.)
- **FR-1.3** 미로그인 상태에서도 홈/게시글/파일 열람 가능(읽기 전용, 선택 인증). 작성·메시지 전송·세션 시작·인터럽트·투표·북마크 등 쓰기/에이전트 동작은 로그인 필요.

### FR-2 인증 / 식별
- **FR-2.1** 회원가입/로그인 시 `username` + `password` 입력 → 서버가 JWT 토큰 발급(`POST /auth/register`, `POST /auth/session`). username 중복 차단(409). 비밀번호는 **bcrypt 해시 저장**. **localStorage에 토큰 저장.**
- **FR-2.2** **API 키 입력/저장 개념이 없다.** 사용자는 LLM 키를 다루지 않으며, 어떤 화면에도 키 입력 필드가 없다. LLM 키는 서버 `.env`에만 존재하고 클라이언트·응답·로그에 노출되지 않는다. (부모 FR-2.2의 "브라우저→Google 직접 호출" 서술은 폐기.)
- **FR-2.3** username은 게시 시 작성자 표시·본인 메시지(우측 버블) 판별에 사용된다. **서버는 JWT 토큰을 검증해 요청 사용자를 식별**한다(헤더 신뢰 폐기).
- **FR-2.4** 로그아웃 시 localStorage의 토큰을 제거한다. (보존해야 할 BYOK 키가 없으므로 부모의 "Gemini 키는 보존" 조건은 삭제.)
- **FR-2.5** 회원가입 시 **비밀번호 + 비밀번호 확인** 두 필드를 입력하고 **두 값이 일치해야** 가입된다(불일치 시 인라인 경고 + 가입 차단). 로그인 모드에는 확인 필드를 표시하지 않는다.
- **FR-2.6** 토큰이 만료/무효이면, 인증 요청이 401일 때 **세션을 자동 정리하고 로그인 모달을 띄운다**. "로그인된 듯 보이나 모든 쓰기가 401"인 좀비 상태를 만들지 않는다.
- **FR-2.7** 게스트·회원 두 모드는 **서버 플래그 없이 런타임에 공존**한다. 분기 기준은 **입력의 비밀번호 유무**다: 비밀번호 **비어있음 → 게스트**(`POST /auth/guest`, 닉네임만으로 즉시 진입), 비밀번호 **차있음 → 회원**(FR-2.1~2.6). 게스트는 **닉네임(최대 16자, `#` 입력 금지)만** 입력하며 서버가 닉네임 뒤에 **`#`+hex 4자리** 식별자를 부여(예: `철수#a3f9`)해 표시·식별에 사용한다(충돌 시 재생성, 회원 username과 충돌하지 않음). 토큰은 **슬라이딩 갱신**(`POST /auth/refresh`)으로 마지막 활동 기준 기본 7일간 유효하며, 게스트는 비밀번호가 없으므로 완전 만료/로그아웃 후엔 같은 정체성으로 재진입할 수 없다. 로그인 화면은 **[게스트]/[로그인] 2탭**으로 제공하고, 기본 탭은 localStorage에 직전 식별(username)이 있으면 [로그인], 없으면 [게스트]로 정한다.

### FR-3 게시글 + 샌드박스 자동 생성
- **FR-3.1** 작성자는 글(제목+본문/작업 지시)을 작성한다(`POST /posts`). 커뮤니티 피커·페르소나 선택은 **없다**(커뮤니티 개념 제거).
- **FR-3.2** 게시 즉시 글이 서버에 **먼저 등록**된다(`{ post, sandbox }` 반환).
- **FR-3.3** **게시글 등록 직후 서버가 샌드박스 디렉토리 1개를 만들고 그 게시글에 1:1(`Sandbox.postId @unique`)로 할당**한다. 준비 중 `status=CREATING`, 폴더/런타임(pi) 메타 준비가 끝나면 `READY`로 전환하고 `sandbox.status` SSE를 통지한다(실패 시 `ERROR`). 동시 생성 수 제한(운영자 비용/리소스 보호) — 초과 시 큐잉 또는 429.
- **FR-3.4** 게시 후 작성자는 곧바로 Thread로 진입하고, 샌드박스가 준비되면 세션을 시작/attach할 수 있다.
- **FR-3.5** 작성자는 자신이 작성한 글의 **제목·본문을 편집**할 수 있다(`PATCH /posts/:id`, 작성자만). 비작성자에게는 [편집] 버튼 미표시(403).
- **FR-3.6 (v2)** 글 작성 화면에 **동시 병렬 협업 opt-in 체크박스**(기본 해제)를 둔다. 체크 시 `POST /posts`에 `concurrent=true`를 보내 이 글의 샌드박스를 v2 병렬 모드(여러 사용자 요청 동시 병렬 추론, 파일/도구 부수효과는 샌드박스 단위 직렬)로 생성한다. 미체크(기본)면 v0.1 직렬 동작이다. 체크박스 옆에는 **짧은 기능 설명 + 경고 문구**(실험적·끄면 순차 처리·동시 요청 수만큼 LLM 비용 증가·같은 파일 동시 수정 시 last-wins)를 i18n 문자열로 노출한다(하드코딩 금지). 모드는 **생성 시 1회 확정**되며 이후 변경할 수 없다.

### FR-4 협업 채팅 스레드 (에이전트 세션)
- **FR-4.1** 스레드 상단에 **원본 글** 고정, 하단은 **채팅방형 버블 리스트**. 버블 정렬·재생 기준은 서버가 부여하는 **`seq`(SoT)** 다.
- **FR-4.2** **타인 메시지 + 모든 에이전트/도구/시스템 버블 = 좌측**, **본인 메시지 = 우측**. 버블 타입: `HUMAN | AGENT_REPLY | TOOL_CALL | TOOL_RESULT | SYSTEM`.
- **FR-4.3** 사람 메시지 전송은 `POST /posts/:id/messages`(본문 `{ body, aiMode, clientId }`). 서버가 `seq`를 부여하고 **SSE fan-out**한다. `clientId`로 멱등(중복 게시 방지).
- **FR-4.4** 다중 사용자가 같은 스레드를 동시에 볼 때(같은 세션 attach), 새 버블·에이전트 토큰·도구 이벤트가 **모두에게 실시간으로 동일하게** 반영된다. v2에서는 **여러 사용자의 요청이 동시에 병렬 추론**되므로, **여러 개의 AGENT_REPLY가 동시에 스트리밍**될 수 있고 각 스트림은 전원에게 중계된다(단일 출력 스트림 가정 폐기). 각 답글은 자기 HUMAN 질문에 1:1로 귀속(`replyToId`)되어 시각적으로 연결된다.
- **FR-4.7 (v2)** **동시 다중 스트리밍 표현**: Thread는 **여러 "타이핑 중" 인디케이터가 공존**할 수 있어야 하며, 내 질문에 달린 답글을 하이라이트/앵커로 식별할 수 있어야 한다. 세션 상태 배지는 단일 RUNNING이 아니라 **활성 턴 수**("N개 작업 진행 중")로 표시한다. Composer 입력은 남의 활성 턴과 무관하게 **항상 즉시 전송 가능**(게이팅 기준이 '세션 단일 streaming'에서 '내 턴'으로 바뀜). 파일 변경은 직렬 적용이라 `file.changed`가 순차 도착하되 빠른 연속 갱신이 있을 수 있다.
- **FR-4.5** 버블은 작성자명/시간/타입을 표시하고, 에이전트/도구/시스템 버블은 시각적으로 구분된다(앰버 틴트 등, 디자인 시스템 §WIREFRAME).

#### FR-4.6 북마크
- **FR-4.6a** 로그인 사용자는 Thread 헤더의 **북마크** 버튼으로 글을 북마크할 수 있다. 낙관적 토글, `POST /posts/:id/bookmark`(idempotent upsert). 실패 시 롤백.
- **FR-4.6b** 해제는 버튼 재클릭, `DELETE /posts/:id/bookmark`(idempotent delete).
- **FR-4.6c** 로그아웃 상태에서 시도 시 로그인 모달을 띄운다.
- **FR-4.6d** 프로필(/me)에 **[ posts | bookmarks ]** 탭으로 북마크한 글 목록(최신 북마크순)을 피드 카드로 노출. 빈상태 카피 제공.

### FR-5 AI on/off — 에이전트 세션
- **FR-5.1** Composer의 **AI 모드 토글**(on/off)이 에이전트 라우팅을 결정한다(부모의 `@AI` 수동 멘션 단축은 없음). **AI on**으로 메시지를 보내면 사람 메시지(HUMAN)가 먼저 등록·fan-out된 뒤, **활성 세션에 입력이 주입되어 에이전트 턴이 시작**된다. **AI off**면 단순 메시지 게시(에이전트 호출 없음, 사람끼리 대화).
- **FR-5.2** 에이전트 턴이 시작되면 해당 턴의 **에이전트 답변(AGENT_REPLY)이 토큰 단위로 스트리밍**(`agent.token`)된다. 답변 버블은 `PENDING→STREAMING→COMPLETE/FAILED`로 확정(`message.updated`)된다. v2에서는 **여러 턴이 동시에 inflight**일 수 있으므로 세션 상태는 단일 RUNNING이 아니라 **활성 턴 수**로 표현된다(활성 턴 ≥1이면 RUNNING, 0이면 IDLE). 각 턴은 독립 스트림이며 자기 질문에 1:1 귀속된다.
- **FR-5.3** AI 모드 기본값은 **서버 런타임 준비 상태**를 따른다(샌드박스가 READY/RUNNING이면 on 가능, CREATING/ERROR면 비활성·안내). 키 유무로 결정하던 부모 정책은 폐기(서버가 항상 LLM을 제공).
- **FR-5.4** 세션 시작/attach는 `POST /posts/:id/session`. 샌드박스가 READY/SUSPENDED면 **pi agent를 spawn**(서버 `.env`의 OpenAI-compatible `apikey`/`baseURL`/`model` 주입, 키는 응답/로그 미포함)하고 `RUNNING`으로 전환한다. **이미 활성 세션이 있으면 새 프로세스 없이 기존 세션에 attach**(fan-out). 샌드박스당 활성 세션(프로세스)은 1개 유지. **v2: 그 단일 세션 안에서 여러 사용자 메시지가 동시 병렬 턴으로 처리되며, 동시 inflight 턴 수는 `MAX_CONCURRENT_TURNS`로 상한**을 둔다(초과분은 공정 큐). 파일/도구 부수효과는 샌드박스 단위 직렬 실행기로 순차 적용된다.
- **FR-5.5** **인터럽트/스티어링**: 진행 중 턴을 `POST /posts/:id/interrupt`로 중단할 수 있다(선택 steer 텍스트). v2에서는 여러 턴이 동시에 inflight일 수 있으므로 **인터럽트는 특정 턴(turnId)을 대상으로** 라우팅되며, 대상 턴만 중단된다(다른 사용자의 진행 중 턴에는 영향 없음). 대상 턴의 STREAMING 메시지는 `COMPLETE`(부분)/`FAILED`로 확정 후 SSE 통지.
- **FR-5.6** 컨텍스트/히스토리/요약은 **pi agent 런타임이 자체 관리**한다. 서버는 컨텍스트를 보관·요약하지 않으며 **메시지/이벤트의 SoT(seq)와 SSE 릴레이만** 담당한다(부모의 128K 클라이언트 요약 엔진은 폐기).

### FR-6 도구 실행 · 파일 조작
- **FR-6.1** 에이전트가 샌드박스에서 도구를 호출하면(`ToolKind = SHELL | FILE_WRITE | FILE_DELETE | FILE_READ | PACKAGE | OTHER`), **TOOL_CALL 버블**(`$ <cmd>` 프롬프트 풍)이 생성되고(`tool.call`), 실행 중 stdout/stderr가 **TOOL_RESULT 버블**에 스트리밍 누적된다(`tool.output`). 종료 시 성공/실패가 확정된다(`tool.result`, 성공=기본 / 실패=term-red).
- **FR-6.2** 샌드박스 디렉토리 **내부는 모든 permission 허용** — 파일 생성/삭제, venv 세팅, 패키지 설치, 쉘 실행이 가능하다.
- **FR-6.3** **파일 변경**은 `file.changed`(CREATED/MODIFIED/DELETED) 이벤트로 통지되어 **워크스페이스/파일 트리 패널**(선택)을 갱신한다. 파일 트리는 `GET /posts/:id/files?path=`, 단일 파일 내용은 `GET /posts/:id/files/content?path=`로 조회한다.
- **FR-6.4** 모든 파일 API와 도구 실행은 **샌드박스 루트 상대 경로를 강제**하고 **경로 탈출(.. / 심볼릭 링크)을 차단**한다(위반 시 400). 바이너리는 메타만/거부, 대용량은 잘라서 반환.

### FR-7 샌드박스 라이프사이클
- **FR-7.1** 상태 머신: **Sandbox** `CREATING → READY → RUNNING → SUSPENDED → (resume) RUNNING → … → cleanup` (+ `ERROR`), **AgentSession** `STARTING → IDLE → RUNNING → INTERRUPTED → STOPPED`(+ `ERROR`). 두 상태는 `sandbox.status`/`session.status` SSE로 클라 인디케이터에 반영된다. **v2: AgentSession의 `RUNNING`/`IDLE`은 단일 턴이 아니라 활성 턴 수의 함수**다(활성 턴 ≥1 → RUNNING, 0 → IDLE). 클라 배지는 "N개 작업 진행 중"으로 활성 턴 수를 표시한다.
- **FR-7.2** **suspend**: 유휴 시 `POST /posts/:id/session/suspend` 또는 유휴 타이머가 pi agent 프로세스를 내리고 `Sandbox.status=SUSPENDED`(디렉토리·파일 보존, 비용/리소스 회수)로 전환한다.
- **FR-7.3** **resume**: SUSPENDED 샌드박스에 새 attach 요청이 오면 프로세스를 다시 spawn(디렉토리 그대로) → READY/RUNNING. 파일 상태는 보존되나 에이전트 인메모리 컨텍스트는 런타임 정책에 따라 재구성된다.
- **FR-7.4** **cleanup**: 게시글 삭제 또는 장기 미사용 정책 시 프로세스 종료 + 디렉토리 정리, `AgentSession.endedAt` 기록(이력 보존).
- **FR-7.5** 에이전트/샌드박스 **상태 인디케이터**가 Thread 화면에 항상 표시된다(부모의 GEMINI 헤더 배지를 대체). 활성=term-amber, 실패=term-red, 유휴=term-dim.

### FR-8 추천(업보트)
- **FR-8.1** 로그인 사용자는 글의 **▲ 점수 버튼**으로 추천(`POST /posts/:id/upvote`, 멱등 upsert). 사용자당 글당 1표(`Vote`), 재클릭 시 취소(`DELETE /posts/:id/upvote`). `score`/`hotScore` 재계산.
- **FR-8.2** ▲ 버튼은 **피드 카드와 Thread 양쪽**에서 동작하며 낙관적 토글 후 서버 점수로 동기화, 실패 시 롤백한다.
- **FR-8.3** 내가 추천한 글은 강조 색으로 표시되고 재로드 후에도 유지된다(서버가 `voted` 계산).
- **FR-8.4** 로그아웃 상태에서 시도 시 로그인 모달을 띄운다.

### FR-9 다국어 (i18n)
- **FR-9.1** UI 언어는 **한국어(ko) / 영어(en)** 를 지원한다. 첫 방문 시 `navigator.language`가 `ko`로 시작하면 한국어, 그 외는 영어. 명시 선택 언어는 `localStorage`에 유지되며 브라우저 기본값보다 우선한다.
- **FR-9.2** 모든 **정적 UI 문구**(버튼·라벨·안내·에러 카피)는 선택 언어로 즉시 전환된다. 사용자 생성 콘텐츠(글 제목·본문, 메시지, username)와 **셸 명령/터미널 출력은 번역하지 않는다**(UGC·코드 비번역 정책 — ShellPrompt 명령어는 인자만 보간).
- **FR-9.3** **에이전트 응답 언어는 가능 범위에서 UI 언어를 따른다**. 세션 시작/메시지 주입 시 활성 언어(`ko`/`en`) 힌트를 런타임에 전달한다.
- **FR-9.4** 언어 전환 UI는 **[ KO | EN ] 세그먼트 컨트롤**(헤더/설정 양쪽)로 제공되며 페이지 리로드 없이 즉시 반영된다(state-based).
- **FR-9.5** 날짜·숫자 등 로케일 의존 값은 `Intl` API로 렌더링한다.
- **FR-9.6** 구현은 외부 i18n 라이브러리 없이 경량 커스텀 스택: `src/stores/langStore.ts`(zustand persist), `src/i18n/dicts/<namespace>.ts`, `src/i18n/useT.ts`, `src/i18n/tn.ts`. 부모의 BYOK 오류 사전은 **서버측 에이전트/세션 오류 메시지**로 의미 교체한다. 누락 키는 개발 환경에서 `console.warn` + 원시 키 폴백.

## 7. 핵심 사용자 흐름 (User Journeys)

### J1. 글 작성 → 샌드박스 자동 생성 → 에이전트 attach
1. 홈에서 인기 게시글 탐색 → 로그인(회원) 또는 게스트(닉네임) 진입 →
2. "글쓰기"(`post --new`) → 제목/본문(작업 지시) 작성 → 게시(서버 먼저 등록 + Sandbox 1:1 자동 생성, CREATING→READY) →
3. Thread 진입, 상단 원본 노출 → 샌드박스 READY 확인 후 세션 시작/attach → 상태 인디케이터 RUNNING.

### J2. 협업 코딩 + AI on (동시 병렬, v2)
1. 다른 사용자가 같은 스레드 세션에 attach(실시간 fan-out) → 우측에 본인 메시지 작성 →
2. **여러 사용자가 동시에 AI on으로 각자 작업 지시** → 각 사람 메시지가 즉시 등록되고 **각자 독립 턴이 동시에 시작**된다(내 요청이 남의 긴 작업 뒤로 밀리지 않음) →
3. **여러 AGENT_REPLY가 동시에 토큰 스트리밍** + 각자의 TOOL_CALL(`$ <cmd>`)/TOOL_RESULT(출력)/file.changed 가 모두에게 실시간 중계 → 각 답글은 자기 질문에 1:1로 연결되어 표시 →
4. **파일 쓰기 등 부수효과는 샌드박스 단위 직렬**로 순차 적용되어 충돌 없이 워크스페이스 패널에 반영(file.changed 순차 도착).

### J3. 인터럽트/스티어링 → suspend → resume
1. 에이전트가 엉뚱한 방향으로 가면 **인터럽트**(선택 steer 텍스트)로 현재 턴 중단 →
2. 유휴가 지속되면 **suspend**(프로세스 내림, 디렉토리 보존) →
3. 다시 누군가 attach하면 **resume**(프로세스 재spawn, 파일 보존) → 작업 이어감.

## 9. 비기능 요구사항 (NFR)

- **NFR-1 모바일 우선**: 360–430px 폭 최적화, PWA 설치 가능(선택), 터치 타깃 ≥ 44px. 워크스페이스/터미널 출력은 모바일에서 가로 스크롤 컨테이너로 격리.
- **NFR-2 보안/프라이버시(서버 키)**: LLM 키(`apikey`/`baseURL`)는 **서버 `.env`에만** 존재하고 클라이언트·응답·로그에 절대 포함되지 않는다. `GET /runtime`은 `model`명·baseURL **호스트 표시까지만** 노출하고 키는 미포함. (부모의 "키는 클라이언트에만" 모델은 폐기.) — TRD §8.
- **NFR-3 샌드박스 격리**: 격리 경계는 (a) **디렉토리 경로 탈출 차단**(파일 API·도구 실행 모두 루트 상대 강제, `..`/symlink 차단), (b) **리소스 제한**(프로세스/메모리/CPU, PoC는 cgroup-lite), (c) **네트워크 정책**. 컨테이너(Firecracker/gVisor/Docker) 강화는 후속.
- **NFR-4 성능**: 홈 피드 LCP < 2.5s, 스레드 초기 50버블 페이지네이션, 토큰/도구 출력 스트림 백프레셔 처리.
- **NFR-5 가용성/확장**: 서버 무상태(stateless) 위주, 수평 확장(SSE 세션은 sticky 또는 pub/sub). 에이전트 프로세스는 호스트에 spawn되므로 세션-호스트 어피니티 고려.
- **NFR-6 신뢰성**: 에이전트/도구 실패 시 사람 메시지는 보존되고 해당 AGENT_REPLY/TOOL_RESULT 버블만 "실패" 상태로 표시(`FAILED`/term-red). 인터럽트는 진행 메시지를 안전하게 확정.
- **NFR-7 비용(서버 부담)**: LLM 비용은 **서버가 부담**한다. 남용 방지는 **글/메시지 레이트리밋 + 샌드박스 동시 생성/실행 수 제한**. (부모의 "서버 LLM 비용 0" 전제는 역전됨.) **v2 주의: 동시 N턴 병렬 추론은 본질적으로 토큰을 N배 소비**하므로, **샌드박스당 동시 inflight 턴 상한(`MAX_CONCURRENT_TURNS`)** 으로 비용/부하를 직접 통제한다(초과분은 공정 큐).
- **NFR-8 동시 병렬 처리 정합성(v2)**: 단일 공유 컨텍스트(convo)를 유지하면서 병렬 턴을 안전하게 처리한다. (a) 각 턴은 시작 시 convo 스냅샷을 읽고 **완료 순으로 직렬 커밋**하여 tool_calls↔tool 결과 짝의 정합을 보존한다, (b) **파일 쓰기·도구 실행은 샌드박스 단위 단일 직렬 실행기**(lock/queue)를 통과해 동시 쓰기 진입을 0으로 만든다(머지 불필요, last-wins), (c) 동시 발사된 턴은 서로의 직전 입력을 못 볼 수 있다(컨텍스트 staleness, 수용된 한계).

## 10. 가정 & 의존성 (Assumptions)

- **A-1** LLM 런타임은 **OpenAI-compatible**이며 `MODEL`/`API_KEY`/`BASE_URL`은 서버 `.env`로 주입된다(PoC 기본 = GitHub Models `https://models.github.ai/inference` · `openai/gpt-4o-mini`, `API_KEY`는 GitHub PAT `ghp_…`). 코드 에이전트 런타임은 **pi agent**(`Sandbox.runtime="pi"`). (TRD §5)
- **A-2** 컨텍스트/히스토리/요약은 **pi agent 런타임이 자체 관리**한다. 서버는 컨텍스트 토큰 한도를 추적하지 않으며, `seq`만 메시지 순서의 단일 출처다.
- **A-3** username은 표시·본인 판별용이며 **DB에서 전역 `@unique`**. 회원은 username 자체가 유일, 게스트는 서버가 부여하는 **`#`+hex 4자리**로 결합 문자열을 유일화한다.
- **A-4** 샌드박스는 게시글당 **1개(`@unique`)** 이며 호스트 디렉토리(path)가 격리 루트다. PoC는 호스트 디렉토리 격리 수준이며 컨테이너 격리는 후속 가정.
- **A-5** 동시 attach/동시 turn 같은 경쟁 상태는 PoC에서 **샌드박스당 활성 세션(프로세스) 1개 + 서버 seq 정렬 + 멱등 clientId**로 단순 처리한다(완전한 분산 합의는 비범위). **v2: 동시 turn은 막지 않고 병렬 허용**하되, 정합성은 **부수효과 직렬화(샌드박스 단위 직렬 실행기) + convo 스냅샷 읽기/완료 순 직렬 커밋 + 답글 1:1 귀속(replyToId)** 으로 보장한다. 같은 파일을 동시에 건드린 턴은 직렬 적용 last-wins이며, 필요 시 같은 파일 대상 턴만 직렬로 폴백한다.

| 공유 세션 일관성(동시 attach·**동시 병렬 turn, v2**) | 출력 분기/순서 꼬임·컨텍스트 정합 깨짐 | 서버가 버블 순서(`seq`)·fan-out의 단일 출처(SoT), 샌드박스당 활성 세션(프로세스) 1개, **부수효과 직렬화 + convo 스냅샷/완료 순 직렬 커밋 + 답글 1:1 귀속**(§NFR-8) |
| **동시 토큰 비용 폭증(v2 병렬 N턴)** | 토큰 N배·비용 급증 | 샌드박스당 **동시 inflight 턴 상한(`MAX_CONCURRENT_TURNS`)** + 초과분 공정 큐, `GET /metrics` 모니터링 |
| **동일 파일 동시 턴의 논리적 레이스(v2)** | 한 턴의 쓰기가 다른 턴을 덮어씀(last-wins) | 부수효과 직렬 적용으로 파일 손상은 없음(머지 불필요), 필요 시 같은 파일 대상 턴만 직렬 폴백 — 정직히 명시된 수용 한계 |
| 에이전트 폭주(무한 도구 호출) | 자원 소진 | 인터럽트/스티어링, 턴/도구 호출 상한, suspend 타이머 |

---

## 12. 마일스톤 (PoC)

1. **M1 — 골격**: 인증(회원+게스트), 게시글 작성, 홈 피드, 추천/북마크.
2. **M2 — 샌드박스 코어**: 글 작성 시 Sandbox 1:1 자동 생성(CREATING→READY), 디렉토리 격리·경로 탈출 차단, 파일 트리/내용 API.
3. **M3 — 에이전트 런타임**: AgentRuntime(pi agent) 어댑터 — spawn/attach/stream/interrupt, OpenAI-compatible LLM(.env) 주입, session/sandbox 상태 머신.
4. **M4 — 협업 스레드/실시간**: 채팅형 버블, AI on/off, SSE fan-out(message/agent.token/tool.*/file.changed/status), 인터럽트/스티어링.
5. **M5 — 다듬기**: 워크스페이스 패널, 인기 정렬, suspend/resume·cleanup, i18n, 에러/로딩 상태, PWA, 지표 계측.

## 13. 수용 기준 (Acceptance Criteria) — 요청 매핑

- [ ] **#1** 홈에 게시글 인기 피드(hot/new) 노출 + 카드에 샌드박스 상태 요약(커뮤니티 검색 없음).
- [ ] **#2** 작성자가 글을 게시하면 **Sandbox가 1:1 자동 생성**되고(CREATING→READY) Thread로 진입.
- [ ] **#3** Thread에서 세션 시작/attach 시 **pi agent가 샌드박스에서 spawn**(서버 .env 키 주입, 키 미노출)되고 다중 클라가 동일 세션에 attach(fan-out).
- [ ] **#4** 스레드 상단 원본 + 하단 채팅형, 타인/에이전트/도구/시스템=좌, 본인=우, seq 정렬.
- [ ] **#5** **AI on** 메시지가 사람 버블 우선 등록 → 세션 주입 → AGENT_REPLY 토큰 스트리밍.
- [ ] **#5b (v2)** 여러 사용자가 동시에 AI on으로 요청하면 **각자 독립 턴이 병렬로 추론**되어 **여러 AGENT_REPLY가 동시에 스트리밍**되고, 각 답글이 자기 질문에 1:1(replyToId)로 귀속된다(내 답이 남의 긴 턴 뒤로 pending되지 않음).
- [ ] **#5c (v2)** 동일 샌드박스에서 동시 턴들의 **파일/도구 부수효과가 직렬로 안전하게 적용**되고(충돌·머지 없음), 동시 inflight 턴 수가 `MAX_CONCURRENT_TURNS` 상한을 지키며 초과분은 큐잉된다.
- [ ] **#6** 에이전트 도구 호출이 **TOOL_CALL/TOOL_RESULT 버블**로 렌더되고 file.changed로 워크스페이스 갱신.
- [ ] **#7** 인터럽트/스티어링으로 진행 턴을 중단하고 진행 메시지를 안전하게 확정.
- [ ] **샌드박스 격리** 파일 API·도구 실행이 루트 상대 경로를 강제하고 경로 탈출을 차단(400).
- [ ] **서버 키** 어떤 화면·응답·로그에도 LLM 키가 없고, `GET /runtime`은 model/baseURL 호스트까지만 노출.
- [ ] **라이프사이클** suspend(프로세스 내림·디렉토리 보존) → resume(재spawn·파일 보존) 동작.
- [ ] **#i18n** UI 언어 토글(KO/EN) 즉시 반영, 에이전트 응답이 가능 범위에서 선택 언어를 따름, UGC·셸 명령은 번역되지 않음, 언어 선택이 localStorage에 유지됨.
