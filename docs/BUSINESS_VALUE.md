# Aidit-Code — 비즈니스 가치 근거 (BUSINESS_VALUE)

> 관련: [PRD.md](./PRD.md) · [TRD.md](./TRD.md) · [PATENT.html](./PATENT.html) · [PAPER.html](./PAPER.html) · [EXPERIMENTS.md](./EXPERIMENTS.md)
> 목적: "기술이 무엇인가"가 아니라 **"누가·왜 쓰고, 왜 우리만 가능하며, 어떻게 돈이 도는가"**를 근거와 함께 못박는다.
> 자매 제품 [Aidit](../../Aidit/docs/BUSINESS_VALUE.md)와의 관계는 §8 참조.

---

## 1. 한 줄 가치 제안

> **"게시글 하나가 팀이 함께 올라타는 라이브 코드 에이전트 세션이 된다. 여러 사람이 동시에 던진 요청은 병렬로 추론되어 각자 답이 즉시 스트리밍되고, 파일 변경 같은 부수효과는 직렬로 안전하게 적용된다."**

Copilot·Cursor·ChatGPT-Code는 **1인 1에이전트**다. Aidit-Code는 게시글마다 **백엔드 샌드박스에서 도는 코드 에이전트**에 팀 전원이 attach해, 토큰·툴콜·파일 변경을 **실시간으로 함께** 본다. v2의 핵심은 **머리-막힘(HOL blocking) 제거** — 내 질문이 남의 긴 작업 뒤에 줄 서지 않는다.

## 2. 문제와 시장

- **문제 A (1인용 에이전트)**: AI 코딩 도구는 개인 IDE에 갇혀 있다. 페어·몹 프로그래밍, 라이브 코드 리뷰, 강의 실습은 "한 명이 운전하고 나머지는 구경"에 머문다. 팀이 **하나의 에이전트를 공동 운전**할 방법이 없다.
- **문제 B (공유 세션의 직렬 병목)**: 순진하게 공유 세션을 만들면 동시 질문이 한 줄로 직렬화돼(단일 활성 턴 + FIFO 큐) 내 요청이 남의 30초짜리 작업 뒤에 묶인다(PRD §Δv2). 협업이 늘수록 대기가 늘어 **협업이 곧 페널티**가 된다.
- **시장**: 개발팀(페어/몹·리뷰), 부트캠프·대학 실습(강사+수강생이 한 에이전트), 기술 면접·라이브 코딩, 인시던트 대응(여러 엔지니어가 한 샌드박스에서 함께 진단).

## 3. 타깃 사용자(ICP)와 쐐기 유스케이스

- **ICP**: **소규모 개발팀·교육 그룹**(3~8인)으로, 실제 코드가 생성·실행되는 협업이 필요한 조직.
- **쐐기 유스케이스**: *"몹 프로그래밍/라이브 코드 리뷰 — 팀이 하나의 샌드박스 세션에서 에이전트를 공동 운전하며, 여러 명이 동시에 '이 API 추가해줘' '이 코드 리뷰해줘'를 던져도 서로 안 기다리고 각자 답이 즉시 흐르고, 파일은 안전하게 순차 적용된다."*
  - 데모(`docs/DEMO_SCENARIO.md`)로 E2E 재현·녹화됨 — 동시 협업·툴콜·터미널·라이브 파일트리·중단/steer까지 "작동"으로 증명.
- **확장**: 강의 실습(강사가 steer로 개입), 기술 면접(면접관+지원자 공유 세션), 온콜 인시던트 룸.

## 4. 차별화 해자 (왜 경쟁자가 못 따라오나)

1. **병렬 추론 + 직렬 부수효과 동시성** — 여러 사용자의 턴이 **독립 turnId로 동시 병렬 추론**되어 즉시 스트리밍되고, 파일 쓰기/쉘 실행만 **샌드박스 단위 단일 직렬 실행기**로 순차 적용된다(PRD §Δv2, 특허·논문). 대안(프로세스 격리=공유 컨텍스트 파괴, 입력 배칭=귀속 붕괴)을 정면 기각한 설계라 모방이 어렵다. **효과는 벤치로 증명**(§7, EXPERIMENTS.md E1/E2).
2. **공유 단일 컨텍스트 멀티유저 에이전트 세션** — 1인 1에이전트가 아니라 **하나의 세션 = 팀 공동 작업공간**. 각 병렬 턴은 시작 시 스냅샷을 읽고 완료 순으로 직렬 커밋해 단일 convo를 유지.
3. **실제 실행 + 실시간 fan-out** — 샌드박스에서 진짜 파일 생성·쉘·패키지 설치가 일어나고, 토큰/툴콜/터미널/파일변경이 SSE로 전원에게 중계된다. "채팅"이 아니라 "함께 보는 실행".

> 경쟁 지형(2×2): **축 = [단일 사용자 ↔ 멀티유저] × [채팅만 ↔ 실제 샌드박스 실행]**. ChatGPT=단일·채팅, Copilot/Cursor=단일·실행, 팀 챗봇=멀티·채팅. **멀티유저 × 실제 실행(+HOL-free 병렬) 사분면은 Aidit-Code 단독.**

## 5. 원가 · 과금 모델 (Unit Economics)

Aidit(BYOK)과 **정반대로, LLM 원가를 서버가 부담**한다. 대신 실제 코드 실행이라는 **고부가 가치**를 제공하므로 관리형 유료 티어로 성립한다.

- **원가 구조**: 동시 N턴 = **N× 토큰**(동시성 본질 비용, PRD가 정직히 명시) + 샌드박스 컴퓨트. 즉 **사용량이 곧 원가**다.
- **그래서 과금은 원가를 반드시 덮어야 한다**: (a) **좌석 구독 + 사용량 미터링**(동시 턴·샌드박스 시간), (b) 팀/기업 관리형 플랜(프라이빗 샌드박스, 저장소 연동, 감사로그), (c) 교육기관 라이선스.
- **원가 방어 레버**(이미 코드에 존재): 게시글별 **동시 턴 상한**(`MAX_CONCURRENT_TURNS`), 추론 강도 선택(낮음/중간/높음)으로 토큰 조절, 모델 티어링(단순작업=경량모델). "동시성은 옵트인(기본 OFF)"이라 원가가 통제된다.
- **가치 정당화**: 몹 프로그래밍 1시간을 절약하면 개발자 인건비가 토큰비를 압도한다 — B2B에서 지불의사(WTP)가 높은 영역.

## 6. Go-To-Market

1. **개발팀 파일럿** — 한 팀이 몹 세션/리뷰에 2주 사용, "동시 턴 수"와 "HOL 대기 감소"를 성공지표로.
2. **부트캠프 실습 통합** — 강사가 steer로 개입하는 라이브 실습. Aidit(커뮤니티) 사용 기관에 자연 업셀.
3. **저장소 연동** — 샌드박스를 실제 repo에 연결(향후) → "팀 AI 코딩 룸"으로 확장.

## 7. 검증 계획 & KPI

- **병렬성 증명 — 통계 실측 완료(2026-07-28, n=180)**: 모의 LLM으로 지연을 결정적으로 주입해
  동시성 계약 3종을 비교했다(하네스 `backend/bench/`, 상세 EXPERIMENTS.md §E2 실측 결과).
  시나리오: A가 길이 L의 작업을 시작하고 **+1초 뒤** B가 한 줄 질문 → B의 첫 토큰까지 시간(TTFT)을 측정.

  | 조건 | L=2s | L=6s | L=15s | TTFT~L 기울기 |
  |---|---|---|---|---|
  | 직렬(v0.1 FIFO) | 1.93s | 5.93s | **14.93s** | **1.000** (완전 종속) |
  | 거절+재시도(경쟁 제품 계열) | 2.26s | 6.30s | **15.39s** | **1.010** (더 나쁨) |
  | **병렬(Aidit-Code v2)** | **0.24s** | **0.24s** | **0.24s** | **0.000** (완전 독립) |

  - **L=15s에서 63.5배**(14.93초 → 0.235초). 셀당 n=20, p95도 p50과 1% 이내로 붙는다.
  - 핵심은 배수가 아니라 **기울기 0**이다 — 남의 작업이 얼마나 길든 내 대기는 늘지 않는다.
    직렬 계약은 협업자가 늘수록 대기가 선형으로 늘어 "협업이 곧 페널티"가 되지만, 우리는 그 항이 사라진다.
  - **경쟁 제품 계열(거절+폴링)이 단순 큐잉보다 나쁘다**는 것이 비자명한 세일즈 포인트다.
  - 재현 가능: `cd backend && npm run bench:e2` — 실 LLM 키·네트워크 불필요, 40분.
  - 한계(정직히): 이 시나리오에서 B는 파일 도구를 쓰지 않아 샌드박스 락을 다투지 않는다.
    두 턴이 **모두** 부수효과를 낼 때의 경합은 후속 실험(E1/E3) 대상. 실 LLM 스팟 대조도 미실시.
  - (2026-07-25 파일럿 n=1 결과 "겹침 94%·벽시계 1.72×"는 위 통계 측정으로 대체됨. EXPERIMENTS.md 부록 A에 보존.)
- **협업성**: 세션당 동시 참여자·동시 턴 수.
- **산출물**: 세션당 생성 파일 수·테스트 통과율, "최종 코드 요약/README 산출" 여부.
- **원가**: 세션당 토큰·샌드박스 시간 대비 청구액(과금이 원가를 덮는지).

## 8. 자매 제품과의 포트폴리오 논리 (Aidit ↔ Aidit-Code)

**같은 코어(멀티유저 공유 AI 세션 + 실시간 fan-out)의 두 응용**이며 **원가 모델이 정반대**라 하나의 사다리를 이룬다.

| | **Aidit** | **Aidit-Code** (본 문서) |
|--|-----------|--------------------------|
| AI 실행 | 클라이언트 BYOK 직접 호출 | 백엔드 샌드박스 에이전트(서버 키) |
| LLM 원가 | 사용자 부담(운영자 ≈0) | **서버 부담** |
| 산출물 | 텍스트 대화 → 문서 | **실제 코드·파일·실행 결과** |
| 포지션 | 제로 한계원가 커뮤니티 티어(획득) | **고부가 관리형 코딩 티어(수익화)** |

→ 결합 전략: **Aidit으로 저원가로 사용자·커뮤니티를 획득**하고, 실제 코드 실행이 필요한 고가치 워크로드를 **Aidit-Code 유료 관리형으로 업셀**. 대화에서 실행으로, 무료에서 유료로.

## 9. 리스크 & 대응

| 리스크 | 대응 |
|--------|------|
| 동시 N턴 = N× 토큰 원가 | 동시성 옵트인(기본 OFF)·동시 턴 상한·추론강도/모델 티어링·사용량 과금으로 원가 전가 |
| 샌드박스 보안(임의 코드 실행) | 격리 샌드박스·리소스 제한(TRD), 신뢰경계·CSP·SSRF 방어(특허 종속항) |
| 같은 파일 동시 수정 레이스 | 직렬 실행기 last-wins + 필요 시 같은 파일 턴만 직렬 폴백(PRD가 한계로 명시) |
| 공유 컨텍스트 조기 포화(멀티유저) | 컨텍스트 상향·요약, 세그먼트 관리 |
| 단일 제공자 종속 | OpenAI-compatible 엔드포인트(`BASE_URL`/`MODEL`)로 제공자 스왑 가능 |
